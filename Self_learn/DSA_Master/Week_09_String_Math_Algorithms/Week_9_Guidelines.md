## 📚 Core Concepts

**Concept 1: String Matching (KMP)**  
O(n+m) via failure function. Preprocessing-based. Avoids redundant comparisons.

**Concept 2: String Matching (Rabin-Karp)**  
O(n+m) average via rolling hash. Simple, extends to multiple patterns and 2D.

**Concept 3: Number Theory**  
Primes, GCD, factorization foundations. Essential for cryptography and number problems.

**Concept 4: Modular Arithmetic**  
Fast exponentiation, inverse, CRT. Critical for RSA, large number operations.

**Concept 5: Computational Geometry**  
Convex hull, point-in-polygon, line intersection. Foundation for graphics and robotics.

## ⚠️ Common Mistakes to Avoid

**Mistake 1: "KMP too complex, just use built-in"**
Reality: KMP elegant, O(n+m) guaranteed, interview favorite. Memorize it.

**Mistake 2: "Hash collisions break Rabin-Karp"**
Reality: Rare, always verify string on hash match. Robust when done right.

**Mistake 3: "Number theory only for cryptography"**
Reality: GCD/LCM for simplifying fractions, finding LCD. Primes for hashing.

**Mistake 4: "Modular arithmetic too hard"**
Reality: Fast exp simple via binary exponentiation. CRT elegant but optional.

**Mistake 5: "Geometry not in coding interviews"**
Reality: 2-5% of medium-hard problems. Convex hull, intersections worth knowing.

## ❓ Frequently Asked Questions

**Q: Is KMP worth memorizing for interviews?**
A: Yes. O(n+m) optimal. Shows deep understanding. Asked occasionally.

**Q: When use Rabin-Karp over KMP?**
A: Multiple patterns, 2D matching, simplicity. Otherwise KMP.

**Q: Do I need to memorize all number theory?**
A: GCD and primes essential. Factorization useful. CRT optional.

**Q: Is modular arithmetic necessary?**
A: For cryptography and large number problems, yes. For general interviews, partial.

**Q: How much geometry is tested?**
A: 2-5% of problems. Convex hull most common. Worth learning basics.

**Q: Can I skip any day?**
A: KMP/Rabin-Karp useful (string problems). Geometry can be partial. Number theory essential foundation.
